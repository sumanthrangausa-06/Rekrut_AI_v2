## 2. Method

`scripts/check-schema-drift.js` (committed on this branch; becomes the CI guard):

1. Extracts SQL string/template literals from **routes/, services/, lib/, workers/, middleware/, server.js**, plus view DDL in migrations 236/237/238/240 (views as reference sources — MUST-4d). `migrate.js` and `migrations/` are excluded as *code* (they are the DDL side).
2. Per query: resolves **alias → table** (MUST-5; unqualified hits are never counted as present), parses SELECT lists, INSERT column lists, UPDATE SET clauses, WHERE/GROUP/ORDER/HAVING references, JOIN equality pairs. Parenthesised subqueries are stripped for outer-scope resolution (their tables are not in the outer scope). Output aliases (`AS x`) are excluded. String literals are stripped before parsing so **JSONB keys are not columns** (SHOULD-6; verified at migrations/138:84-85, where `auto_send_on_apply` appears only as a JSON key).
3. `SELECT *` / `alias.*` + JS property access (MUST-4a): precise assignment tracking — the star query must be the argument of `const X = await ….query(…)`, row vars are `Y = X.rows[0]` / `X.rows.map(r => …)`; only `Y.<prop>` accesses count.
4. Column-name arrays feeding dynamic SQL (MUST-4c): only counted when every element is snake_case and the region builds `` `${field} = $n` `` fragments (the candidate-preferences.js:75,108,150 pattern — its fields all exist on `candidate_profiles`, correctly producing no finding).
5. Client-payload-derived expectations (deliverable 3b): company profile update (`routes/company.js:355ff`, static `COALESCE($n, col)` SET list) and job create/update (`routes/recruiter.js:770`, `:1151` INSERT/SET lists) destructure `req.body` fields that map 1:1 onto the captured INSERT/UPDATE column lists — the payload expectations are therefore already in the findings (companies.* and jobs.auto_send_* rows below).
6. Compares per table against the fresh DB's `information_schema`; classifies chain status: `NEVER_CREATED` (no DDL lands it on a fresh build — includes bootstrap-shadowed twins whose DDL ran as a no-op), `CREATED_POST_P2_HALT` (sole DDL sorts at/after the halting file), `WRONG_TABLE` (no DDL for this table; the name exists on a different table — the trap class), `TYPE_MISMATCH` (JOIN equality operands of different type families).
7. **Bootstrap shadow register (MUST-2):** all 13 `migrate.js` bootstrap tables enumerated — `_migrations, users, jobs, interviews, interview_questions, agent_data, refresh_tokens, password_reset_tokens, oauth_connections, companies, recruiter_join_requests, referral_rewards, candidate_profiles, saved_jobs` — each diffed against its first later `CREATE TABLE` twin. **18 twin columns are absent from the fresh DB** (the companies 8, rjr.requested_at, saved_jobs.saved_at + notes, referral_rewards type drift, candidate_profiles/users latent columns, companies.verified_at latent).

**Red-first proof:** on pristine `dev` (this branch's base) the script exits **1** with **263 findings** (115 NEVER_CREATED, 122 WRONG_TABLE, 25 CREATED_POST_P2_HALT, 1 TYPE_MISMATCH) from 13,021 extracted references / 2,511 distinct table.column pairs. ## 6. Unresolvable / dynamic-SQL register (253 entries — summary)

- `interpolated-sql`: template literals containing `${…}` (static parts still parsed; identifier interpolation is the risk — full list regenerable via the script's DYNAMIC section).
- `unqualified-multitable`: bare select-list identifiers in multi-table queries that exist on a scoped table (not findings, by design).
- `select-star-untracked`: `SELECT *` queries whose result variable could not be assignment-tracked (registered, not guessed).
- `column-name-array`: snake_case arrays not matching the dynamic-SET pattern (registered only).
- Known extractor limits (stated, not hidden): subquery/JOIN scope flattening can attribute a property to the wrong table in LOW/MEDIUM tiers (e.g. the recruiter.js candidate-list cluster, aptitude subquery cluster) — that is exactly why SHOULD-7 makes the manifest human-reviewed before the guard enforces it.
