## Common Pattern: Loading States

### Problem
Many pages in Rekrut AI show a loading spinner while fetching data from the API. If E2E tests check for content immediately after `networkidle`, they will fail because the content hasn't rendered yet.

### Affected Pages

| Page | Loading Indicator | Data Fetched | Test File |
|------|------------------|--------------|-----------|
| `/candidate/ai-coaching` | `.animate-spin` | stats, questions, progress | `e2e/ai-coaching-flow.spec.ts` |
| `/candidate/jobs` | `.animate-spin` | jobs list, recommended jobs | `e2e/candidate-critical-flow.spec.ts` |
| `/candidate/dashboard` | `.animate-spin` | applications, stats | `e2e/candidate-dashboard.spec.ts` |
| `/recruiter/dashboard` | `.animate-spin` | jobs, analytics | `e2e/recruiter-critical-flow.spec.ts` |

### Solution

Always wait for loading spinners to disappear before asserting on content:

```typescript
// ✅ CORRECT — Wait for loading to finish
await page.goto('/candidate/ai-coaching')
await page.waitForLoadState('networkidle')
await page.locator('.animate-spin').waitFor({ state: 'detached', timeout: 10000 })
await expect(page.getByRole('heading', { name: /AI Interview Coach/i })).toBeVisible()

// ❌ WRONG — Heading may not exist yet
await page.goto('/candidate/ai-coaching')
await page.waitForLoadState('networkidle')
await expect(page.getByRole('heading', { name: /AI Interview Coach/i })).toBeVisible()
```

### Why This Happens

The React components use a `loading` state:

```tsx
// client/src/pages/candidate/ai-coaching.tsx
const [loading, setLoading] = useState(true)

useEffect(() => {
  Promise.all([loadStats(), loadQuestions()]).finally(() => setLoading(false))
}, [])

if (loading) {
  return (
    <div className='flex items-center justify-center py-20'>
      <div className='animate-spin rounded-full h-8 w-8 border-b-2 border-primary' />
    </div>
  )
}

return (
  <div>
    <h1>AI Interview Coach</h1>  {/* Only visible after loading */}
  </div>
)
```

`networkidle` fires when network requests stop, but React may still be re-rendering after the data arrives.

## Auth Setup Failures

### Known Issue: Admin Auth
The admin auth setup (`e2e/auth.setup.ts`) often fails with 401 "Invalid credentials" because:
- The admin password is set via `ADMIN_PASSWORD` env var
- In CI, this env var may not be set or may be incorrect
- **Impact:** Admin-related E2E tests are skipped, but candidate/recruiter tests still run

### Workaround
Admin tests should use `test.skip()` when credentials are unavailable:

```typescript
const ADMIN_PASSWORD = process.env.ADMIN_PASSWORD || ''
if (!ADMIN_PASSWORD) test.skip()
```

## CI/CD Debugging

### Where to Find Logs

| Resource | URL |
|----------|-----|
| GitHub Actions | `https://github.com/sumanthrangausa-06/Rekrut_AI_v2/actions` |
| Render Dashboard | `https://dashboard.render.com` |
| Staging Health | `https://rekrutai-staging.onrender.com/health` |
| Production Health | `https://rekrutai.co/health` |

### Reading CI Failures

1. Find the failed job (usually "E2E Tests (candidate)" or "E2E Tests (recruiter)")
2. Expand "Run E2E tests" step
3. Look for "Testing stopped early after X maximum allowed failures"
4. The first failure is usually the root cause

### Local Reproduction

```bash
# Run specific test file
BASE_URL=https://rekrutai-staging.onrender.com npx playwright test e2e/ai-coaching-flow.spec.ts

# Run with UI for debugging
BASE_URL=https://rekrutai-staging.onrender.com npx playwright test e2e/ai-coaching-flow.spec.ts --ui

# Run smoke tests only
BASE_URL=https://rekrutai-staging.onrender.com npx playwright test e2e/smoke-test.spec.ts
```

## Test Data & Fixtures

### Test Accounts (Staging)

| Role | Email | Password | Used In |
|------|-------|----------|---------|
| Candidate | e2e-candidate@rekrutai.test | TestPass123! | Candidate flows |
| Recruiter | e2e-recruiter@rekrutai.test | TestPass123! | Recruiter flows |
| Admin | admin | (ADMIN_PASSWORD env) | Admin flows |

### Auth State Files

These are generated by `e2e/auth.setup.ts` and cached between runs:
- `e2e/.auth/candidate.json`
- `e2e/.auth/recruiter.json`
- `e2e/.auth/admin.json`

Delete these files to force re-authentication.
